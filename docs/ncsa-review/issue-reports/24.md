## Deviations from the plan

1. **Test loading.** The plan's spot check says `constants.ts` has no imports and can run under `--experimental-strip-types`. That does not extend to this test: `useDataset.ts` uses extensionless imports and `constants.ts:37` reads `import.meta.env`, which throws under plain Node. The test loads the real module with Vite's `ssrLoadModule`, already a dev dependency, with its cache directory in temp so the shared `node_modules` is not written. No new dependency.
2. **Test file name.** Used `tests/dataCache.test.mjs` rather than adding to the plan's `tests/analytics.test.mjs`, which belongs to the batch 3 helper work. The `test` script glob picks up both.
3. **Same plan bullet, not done here.** `fetchMeta` and `population_note` in the batch 3 `useDataset.ts` bullet are #16 and another issue's. #24 does not need them.

## Shared helpers and merge notes

- No new shared helper. `invalidateDataCache` stays exported, now used by the interceptor and the test.
- The `"test"` line in `package.json` is the one the plan names, so another issue adding it should merge to the same text.
- `AdminPanel.tsx`: if #11 reworks the upload handler in the same lines, keep the call removed.
- Once #16 routes `App.tsx:357` through `fetchMeta`, `/meta` is cleared by this interceptor too.

## Behavior to be aware of

- Accepted in the plan: preset saves, threshold edits and user admin writes also clear the cache, so the next view refetches. Display only.
- Views already mounted do not refetch on their own. This fix relies on routes remounting on navigation, which they do, since `App.tsx:373-384` uses plain `Routes`.
