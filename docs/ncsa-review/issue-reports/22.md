## Deviations from the plan

- **No outline removal to override.** The plan says to override `MapView.css`'s removal of the outline, but at `3775601` that file already sets an outline on `.leaflet-interactive:focus-visible`. I kept it and added the stroke rule, since the outline draws a rectangle around the county's bounding box rather than following its shape. The rectangle is still visible in the screenshot and it does stay visible where neighbors overlap the stroke. The owner may prefer to drop it.
- **Regression test is a new script, not an extension of the reviewer's repro.** That repro was not in the repo. No `package.json` script was added, to keep merges simple.

## Known limits, left as is

- Neighbors painted later can overlap the focus stroke (the limit the plan names).
- Hovering a county other than the focused one still reorders that county, so tab order can shift after mouse use. Focus itself is unaffected.
- From reading the code, not observed: hovering then leaving a keyboard-focused county runs the `mouseout` handler, which restores band styling and closes the tooltip. The CSS stroke stays.
- The `key` on `LeafletGeoJSON` still rebuilds all 102 layers when cause, year or overlay changes. The proposal notes this drops focus. The plan does not assign it to #22, and those controls sit outside the map, so a county normally does not hold focus at that moment.
- 102 tab stops remain. The proposal's county list option is for accessibility sign-off.
- `map-focus.mjs` needs a running backend, like `smoke.mjs`, and is not wired into CI.
