## What it does

- Public: data GETs, `/export/csv`, GET `/annotations`, `/thresholds`, `/presets`, `/auth/me`, `/health`.
- Any allowlisted identity: preset create and delete. Editor: annotation writes. Admin: threshold writes and all `/admin/*`, including GETs.
- Signed in through SSO but not allowlisted: reads only, 403 on writes.
- The identity header counts only with the shared secret header (`hmac.compare_digest`). A repeated or comma-joined identity is refused.
- Writes in hosted mode must carry an `Origin` equal to `IDPH_AUTH_PUBLIC_ORIGIN`, because the proxy cookie travels cross-site and multipart uploads get no preflight.
- Failing closed: with `IDPH_AUTH_MODE` unset or any setting invalid, uvicorn exits with code 3. Guards also answer 503 if a request arrives anyway.
- No historical password or JWT secret is reused. The code has no passwords, no JWT and no default secret. No secret was rotated or printed. Tests generate theirs at run time.

## What NCSA must supply

1. An OIDC or Shibboleth proxy in front of the backend, with TLS (for example oauth2-proxy or mod_auth_openidc).
2. The identity header name and its content, such as eppn or email. Values must match `[A-Za-z0-9._@+-]`, up to 254 characters.
3. A fresh random shared secret of 32 or more characters, its header name, and secret storage for it. Set `IDPH_AUTH_PROXY_SECRET`, `IDPH_AUTH_SECRET_HEADER`, `IDPH_AUTH_USER_HEADER`.
4. Replacement, not appending, of client copies of both headers on every request.
5. Optional-auth behavior on all paths: forward the identity when a session exists, let anonymous requests through otherwise. Public reads depend on this.
6. Sign-in and sign-out URLs (`IDPH_AUTH_LOGIN_URL`, `IDPH_AUTH_LOGOUT_URL`): a site path or an https URL.
7. The public origin (`IDPH_AUTH_PUBLIC_ORIGIN`, `https://host`).
8. A network rule making the backend port reachable only through the proxy.
9. A `SameSite=Lax` or stricter session cookie, and a request body size cap. See the upload caveat below.
10. A persistent location for the allowlist file outside the repo (`IDPH_AUTH_ALLOWLIST_FILE`), plus the volume already needed by #13.

## Keeping local development working

`uvicorn main:app` with no settings now refuses to start. This is the one change to the daily workflow:

```bash
cd app/backend
IDPH_AUTH_MODE=local-dev uvicorn main:app --reload --port 8000
# PowerShell: $env:IDPH_AUTH_MODE='local-dev'; uvicorn main:app --reload --port 8000
```

- Requests from this machine act as admin. `IDPH_DEV_ROLE=editor` or `viewer` tries the other roles.
- Treated as anonymous: another machine, a non-local `Host`, or any forwarding header. Cross-site writes get 403.
- The mode refuses to start if `IDPH_AUTH_PROXY_SECRET` is set.
- The frontend needs no change. `npm run smoke` needs the backend started this way, and its hint now says so.

## Deviations from the plan and proposal

1. The plan says DEFER-MIGRATION and no edits. This was overridden by the owner's exception for this worktree only.
2. Added beyond the proposal's text, because this model needs them:
   - The shared secret header, which the proposal lists only as a risk.
   - The `Origin` check on writes.
   - `GET /auth/me`.
   - Explicit `local-dev` mode.
3. Anonymous reads hide `created_by` and `notify_email`. Public GETs would otherwise expose staff identities and alert addresses.
4. Anonymous exports are no longer audited, since public traffic could otherwise grow the log without limit. Exports by allowlisted users still are.
5. The Export button now shows to everyone, and a non-admin no longer gets `DataTab` as the default tab.
6. Preset writes require allowlist membership, not just any campus login, because presets default to public.

## Known limits

- FastAPI parses a multipart body before dependencies run. An anonymous upload gets 401 and changes nothing, but its body is spooled to temp first. Hence the proxy body cap above. This overlaps #28.
- `request.client.host` in the audit log will be the proxy's address unless uvicorn is told to trust it (`--forwarded-allow-ips`).
- Local-dev trusts its checks, not the deployment. A same-host proxy that sends no forwarding headers and rewrites `Host` to localhost would defeat them. It must never be set on a hosted server.
