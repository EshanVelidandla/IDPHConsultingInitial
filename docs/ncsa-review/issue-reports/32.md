## Deviations from the plan

1. A wrong method on a real API path stays 405 with an `Allow` header (DELETE `/meta`, and HEAD `/meta`). A plain all-method catch-all would have turned these into 404. The plan only asked for unknown paths to be 404.
2. HEAD on a client route now returns 200 instead of 405, as a side effect of the catch-all accepting HEAD. Tested on `/map`.
3. Crumb matching became exact rather than by prefix, so `/map/x` shows "Not found", matching what the router renders.
4. While editing an annotation with no county list, the select still shows the county being edited, and the edit can be saved. This branch was not exercised by a test.
5. Unknown browser paths still get the shell with a 200 (needed for the client not-found page), so no HTTP 404 reaches browsers for them. That is what the plan specifies.
6. The plan named `test_routing.py` updates only; `smoke.mjs` also changed, because the plan's acceptance for `/nope` is in smoke. It may need a merge with #30 or any other batch touching `smoke.mjs`.
