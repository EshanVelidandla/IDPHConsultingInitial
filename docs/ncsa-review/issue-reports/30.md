## What the script does now

- Keeps the health check and exit 2.
- `unhandledRejection` and `uncaughtException` handlers charge the crash to the current route and continue. A crash between routes still fails the run.
- `XMLHttpRequest` is wrapped in `beforeParse`: counts requests per path, fails the route on network error, timeout or status >= 500, and redirects `SMOKE_FAIL` matches to a closed port.
- Routes are objects with `path`, `minChars`, optional `action(window)`, and `check({ doc, text, requests })`. `requests` is there for #21's request count.
- Every route has a data assertion, so no route is declared static.

| Route | Assertion | Kind |
| --- | --- | --- |
| `/` | Sidebar "Years dddd – dddd", from `/meta` | Text proxy. The page body is static copy, so this only proves `/meta` |

| `/insights` | After picking Total Deaths: "Highest county rate" followed by a number | Text proxy, charts have no marks |

## Deviations from the plan

1. **Port.** Port 8130 was already held by `python -m uvicorn main:app --port 8130` (PID 21180, started 2026-11-02 21:38), which I did not start. I left it running and did not use it, because I could not tell which var directory it writes to. My backend ran on OS-assigned port 58448 and has been stopped. **PID 21180 is still running and needs the orchestrator's attention.**
2. **Var override.** `IDPH_VAR_DIR` (plan 0a) does not exist in this worktree and is not #30's item, so I did not add it. A launcher script outside the repo moved the var paths to a temp directory at runtime. The launcher is not in the patch.
3. **Interim `/admin` failure.** The plan expected `/admin` to fail until batch 6. In a normal run it passes, because `/admin/datasets` succeeds. It only fails when that request fails, as in the `SMOKE_FAIL='.*'` run.
4. **`test` script.** Not named in the #30 spec, but the #21 report assigns it to #30's harness. The glob picks up the test files from #21 and #25 after merge.
5. **Test harness.** Stub-backed, with no positive case in the automated test. The passing path was verified only by the manual run against the real backend above. The tests skip if `app/backend/ui/index.html` is missing, so a fresh checkout must build first.

## Notes for merge and later checks

- **Git Bash mangles `SMOKE_FAIL`.** A value starting with `/` is rewritten to a Windows path, so the regex silently matches nothing and the run passes. I saw this: `SMOKE_FAIL='/death_rates'` gave 10 of 10 ok without `MSYS_NO_PATHCONV=1`. #21's acceptance run (`SMOKE_FAIL='/provider_data'`) needs that variable under Git Bash, or a value without the leading slash. `SMOKE_FAIL='.*'` is not affected.
- **#21 action.** Add `action` to the `/scorecard` route, and read counts from `requests` in `check`.
- **Text assertions depend on UI copy.** Issues that reword these labels must update `ROUTES`: "Highest county rate", "Priority counties", "Well-served", "IL counties shown", "mini-maps", "cause files on disk", "All-cause rate / 100k". A reword fails loudly, so it cannot produce a false pass. #14's color sweep is not affected, since the map check compares distinct fills, not specific colors.
- **`README.md` not edited.** Line 91 still describes smoke as "every route renders", and `npm test` is undocumented. Left for batch 7 to avoid a docs conflict.
