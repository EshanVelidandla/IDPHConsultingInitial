## Deviations from the plan

None in behavior. Choices the plan did not spell out:

- A POST that still sends `notify_email` returns 200 and the field is ignored and not stored, including an invalid address that used to return an error. This is default pydantic behavior for unknown fields.
- Updating an old record removes its stored email. Records not updated keep the field on disk, hidden from GET and POST responses.
- The POST response is filtered as well as GET, so one update cannot return another record's email.
- `_EMAIL_RE` was removed because #34 left it with no users. If another issue's batch starts using it, the merge needs to keep it.
- The page intro text ("alert thresholds") was not named in the plan but made the same false claim, so it changed too.
