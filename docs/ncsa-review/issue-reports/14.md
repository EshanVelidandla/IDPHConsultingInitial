## Deviations from the plan

1. **"Each ink token at least 4.5" cannot hold for `--ink-5`,** which the plan keeps at 3.99 / 3.75 / 4.16. The test requires 4.5 for ink through ink-4 and 3:1 for ink-5.
2. **New optional band field `line`.** No-data's `border` stays `D_NULL`, but it reaches only 1.34 on the no-data fill, so a dash in it is close to invisible. `line: INK_4` gives 3.91. I did not change `border` because Pulse's `tileColorRich` uses it as a fill.
3. **No-data dash changed from `1 3` to `3 3`.** The existing `1 3` was already present but renders as dots with round caps.
4. **`getStyle` picks the no-data band from the fill** (`fill === D_NULL_TINT`), so the cue also appears under a provider overlay, and a missing value no longer gets a green border. This overlaps #29 and #5a, which rewrite these lines: **expect a merge conflict in `getStyle`.** Keep this rule or an equivalent one. Until #5a merges, a real zero also shows as no-data, matching its existing fill.
5. **`FieldRow` with no direct control** (the Visibility radio group) renders `role="group"` with `aria-labelledby` and no `htmlFor`. A `for` on one radio would select it on click.
6. **`FieldRow` is now exported** so the test can render it.
7. **Scorecard's sort icon** moved to `--ink-4`, though it is non-text, to meet the "borders or separators only" acceptance.
8. **Test file name:** `tests/a11y.test.mjs` rather than the plan's `logic.test.mjs`, to avoid an add/add conflict with Batch 1.
