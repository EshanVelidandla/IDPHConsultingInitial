## Deviations from the plan
None in behavior. Details the plan left open:
- Order comes from the stamp in the name, not mtime, because a restore or volume copy can reset mtimes.
- Older second-resolution names are recognized and sort correctly, so a pre-existing original stays the protected oldest. None exist in the main checkout today.
- Names that do not parse are never pruned and do not count toward the limit.
- A failed removal logs a warning and does not fail the upload or delete.
- Tests call `_backup_dataset` directly rather than POST `/admin/upload`, so the #28 validator and the #13b overlay cannot break them when merged.

## Known limits
- If a backup write fails partway, as on a full disk, the partial file stays and the upload aborts before the table is replaced. It would count as a backup. Not handled, not in the plan.
- "The oldest" is the oldest backup on disk, which is the pipeline original only if the first backup was taken from it.
- Concurrent uploads were not exercised. Names cannot collide, and a removal that loses a race only logs.
