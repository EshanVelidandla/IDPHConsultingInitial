## What changed

- `providerStatus: 'idle' | 'loading' | 'done' | 'error'`. The effect depends on `[showProvider, providerStatus]` and fetches only from `idle`. Full and partial failure both end in `error`; full success ends in `done`. Neither returns to `idle` by itself, so a failure cannot refetch.
- The toggle's click handler moves `error` to `idle`, which arms the retry. Successful metrics stay in the `useDataset` cache, so a retry refetches only the failed ones.
- Provider failures now show an inline `role="alert"` message under the legend strip, listing the metrics that failed. Partial results stay in the table.

## Deviations from the plan

1. **Added the inline provider error, which the plan does not name.** The old `setError` call hit the page-level `if (error) return <banner>`, which removed the table and the toggle. The plan's "toggling off and on retries" could not happen with the toggle gone. Provider failures no longer use page-level `error`, which stays for death rates only.
2. **The retry is armed in the click handler,** not through a second effect. The effect's dependencies are as the plan specifies.
3. **Partial failure ends in `error`,** which the plan allows ("`error` or `done`"), so the failed metrics are named and can be retried.
