**The 5 failures are not from this change.** The same 5 pipeline tests fail in W before any edit, with `FileNotFoundError` on a table that exists. The path is over the Windows 260 character limit (264 for the Cerebrovascular table) because W sits deep in the temp folder. A temporary junction under the scratchpad did not help, and the same tree copied to `<local path>` passed all of them. That copy is deleted.

**Count against the baseline of 66.** No single run shows every test passing, because a run at W's path hits the path limit and the short-path copy skips the 12 UI-dependent tests. Between the two runs, all 73 tests (66 plus 7 new) passed at least once: the 12 skipped tests passed in W with the UI built, and the 5 failures passed in the copy.

**UI items are verified by test only.** The jsdom render is a one-off harness in the scratchpad, not a lasting regression test, because the repo has no frontend test runner. It was not seen failing before the fix, and no real browser or layout was checked. The server ran on port 8110 with a temp store and has been stopped.

## Needs the owner, NCSA or IDPH

- **Owner (Q8):** keeping ILLINOIS as an annotation target is the current default. To reverse it, exclude `ILLINOIS` from the allowlist or the select. If reversed, also change `test_statewide_row_stays_an_annotation_target`.
- **NCSA:** suggested severity is Low, because the stored string renders as escaped text and the form is admin-only. Keep Medium if NCSA weights stored-input validation for the hosted build.
- **Existing data:** annotations already stored with an invalid cause are not cleaned up. From reading the code, not run: `startEdit` loads the stored cause into form state and the PUT sends it, so editing such a row gets a 400, shown in the form, until a valid cause is chosen. The select would show "All causes" for such a row, so the error can look contradictory. The check is worth running on any instance that may hold such rows.
- **Pipeline:** the long-path failures affect any worktree this deep, so the merged result is worth a full pytest run from the main checkout.
