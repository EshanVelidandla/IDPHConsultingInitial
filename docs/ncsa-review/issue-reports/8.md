## Findings the owner should see

1. **The current tree still holds literal seed passwords.** `_generate_initial_users` in `app/backend/auth.py` stores two non-empty plain-text literals in `password_hash` (lines 36 and 45). A fresh repo cut from this tree would carry them into its first commit. Left untouched, since auth is deliberately bypassed and #1 owns it. Gate 3 covers this.
2. **Archiving does not hide anything.** The proposal says "this repo archived" and gives the audit log IPs as the reason to move. An archived public repo is still public, so the IPs stay exposed unless the old repo also goes private or is deleted. Decision D2 below.
3. **The changelog claim Matt corrected is still there.** `CHANGES-issue-remediation.md:142` says nothing in history is a live credential once auth is rebuilt. Left unchanged here. Replace it with the statement below at #1 closure.
4. **No JWT code remains in the tree.** `main.py` and `auth.py` have no JWT or secret handling at `3775601`, so the new secret arrives with #1, not with the migration.

### Cut and verify

5. Use a fresh clone, never a copy of a working directory. A copy would bring `app/backend/var/`, which holds the plain-text user store and the audit log.

   ```
   git clone --branch pre-migration <old repo url> idph-new
   cd idph-new
   git lfs pull
   git rev-parse "HEAD^{tree}" > ../old-tree.txt
   rm -rf .git
   git init -b main
   git lfs install --local
   git add -A
   gitleaks dir . --redact --verbose
   ```

   Stop here if gitleaks reports anything. After gate 3 it should report nothing; `auth.py:36` and `:45` appearing means gate 3 was skipped.

6. Commit, then check before any push:

   ```
   git commit -m "Initial commit, migrated from the review-remediated tree"
   git rev-list --count HEAD                      # must be 1
   git rev-parse "HEAD^{tree}"                    # must equal old-tree.txt
   git log --all -- processin/backend/users.json  # must be empty
   git cat-file -e f1a9aa1                        # must fail
   git lfs ls-files | wc -l                       # 12 at 3775601, unless D5 changed it
   ```

   Equal tree hashes prove that nothing else entered or dropped out. Any change made after the tag breaks this check, so make those changes on the old repo before tagging, or as a second commit in the new one.

7. Create the new empty repo with NCSA, then push the commits and the LFS objects:

   ```
   git remote add origin <new repo url>
   git lfs push --all origin
   git push -u origin main
   ```

   On a separate fresh clone of the new repo, check that the `.asc` files are real data and not pointers, then run the pytest suites and `npm run typecheck`. Use a short path on Windows, because this repo's pipeline tests exceed the 260 character limit under long paths.

8. Turn on scanning: copy `.pre-commit-config.example.yaml` to `.pre-commit-config.yaml`, check the pinned rev, run `pre-commit install`, and add the same scan to CI with history fetched. Enable GitHub push protection if the new host offers it. CI is what counts, because a local hook can be skipped.

### Secrets and old repo

9. **Never reuse a historical JWT secret or password.** This is the rule Matt asked to have stated. Generate a new secret and send it straight to NCSA's secret store. Never paste it into a file, a chat or an issue:

   ```
   python -c "import secrets; print(secrets.token_urlsafe(48))"
   ```

   The code must have no default and must refuse to start without it (#1, step 4). Generate new values rather than comparing them against old ones, since comparing means handling the old ones. Do not copy `users.json` or any audit log from an old host onto the new volume (#13). Start them empty.

10. Rotate every inventory item still in use on any host, then shut down any old deployment. Do this even under options 2 and 3, because rewriting history does not retract what was already public.

11. Apply D2 only after the new repo is verified, so there is always one working copy. Before that, check forks and clones on the old repo: forks of a public repo stay public and are outside your control, so contact their owners if there are any.

12. Ask GitHub support to purge cached views of the old commits, naming `processin/backend/users.json` and `processin/backend/audit.json`. Decide with IDPH whether the exposed IPs need any notice. That is their call and is not assessed here.

13. Close out: post the statement above at #1 closure, fix `CHANGES-issue-remediation.md:142`, close #8 and #37e, and update links to the old repo in NCSA's docs.
