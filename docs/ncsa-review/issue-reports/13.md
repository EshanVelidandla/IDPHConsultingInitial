## Deviations from the plan

1. `_dataset_path` returns None when neither overlay nor committed file exists, as well as for a tombstone. The plan's wording only names the tombstone. Needed so a missing file gives the existing 404.
2. `_effective_datasets` filters on the full `_death_rates_by_county_year.csv` suffix. `/admin/datasets` used to list any `.csv`. All 15 files in `static/death_rate_tables/` carry the suffix, so the listing is the same.
3. `auth.py` no longer calls `os.makedirs` because `storage` does it on import. This is part of the plan's var root, outside the three functions named in the scope guard, and touches no auth behavior.
4. `_load_county_names` not changed. It still reads the first committed table, which is now stable because `static/` is never written. #28 owns moving it to the population file. The proposal listed it as needing the overlay lookup; it no longer does.

## Behavior the owner should know

An uploaded table keeps priority over `static/`, including over a newer pipeline build that ships later, until it is deleted. Deleting then leaves a tombstone, which hides the committed table too. **There is no endpoint to revert to the committed table:** today that means removing the files in `var/datasets/` by hand. This follows the plan as written and is noted in the README layout entry for the priority rule only.
